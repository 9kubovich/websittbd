SQL: реляционные базы данных

Таблицы, ключи, связи и язык запросов, на котором работает большая часть веба.

Реляционная модель

Каждая таблица описывает одну сущность: пользователей, товары, заказы. Строка — отдельная запись, столбец — её свойство с заданным типом. Уникальность записи обеспечивает первичный ключ, а связь между таблицами задаёт внешний ключ.

Схема определяется заранее. Это удобно для контроля данных, но изменения структуры требуют миграций.

Популярные СУБД

  • PostgreSQL — мощная открытая СУБД с богатыми типами данных и JSONB.
  • MySQL / MariaDB — стандарт хостинга и CMS, например WordPress.
  • SQLite — база в одном файле, подходит для прототипов и мобильных приложений.
  • Microsoft SQL Server — корпоративное решение экосистемы .NET.

Основные запросы

Язык SQL делится на команды выборки, изменения и описания структуры. Пример выборки последних заказов пользователя:

SELECT o.id, o.created_at, SUM(i.price * i.qty) AS total
FROM orders AS o
JOIN order_items AS i ON i.order_id = o.id
WHERE o.user_id = 42
GROUP BY o.id, o.created_at
ORDER BY o.created_at DESC
LIMIT 10;

CRUD: создание, чтение, изменение, удаление

Почти любая работа с таблицей сводится к четырём операциям, которые вместе называют CRUD (Create, Read, Update, Delete):

-- создать запись
INSERT INTO users (name, email) VALUES ('Анна', 'anna@example.com');

-- изменить запись
UPDATE users SET name = 'Анна Иванова' WHERE id = 42;

-- удалить запись
DELETE FROM users WHERE id = 42;

Типы данных

Для каждого столбца заранее указывают тип данных, который он будет хранить. Основные типы почти одинаковы во всех СУБД:

  • INTEGER — целое число, например возраст или количество товара.
  • VARCHAR(n) — текст ограниченной длины, например имя или email.
  • TEXT — длинный текст без ограничения, например описание товара.
  • BOOLEAN — логическое значение true/false.
  • DATE / TIMESTAMP — дата или дата со временем.
  • DECIMAL(p, s) — точное число с фиксированной точностью, для денег.

Транзакции и ACID

Транзакция объединяет несколько операций в одну: либо выполняются все, либо ни одна. Принципы ACID — атомарность, согласованность, изолированность и долговечность — защищают данные от сбоев, например при переводе денег между счетами.

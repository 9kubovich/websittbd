ORM и работа из приложения

Как веб-приложение обращается к базе: драйверы, ORM и REST API.

Путь запроса

Браузер никогда не обращается к базе напрямую. Клиент отправляет запрос на сервер, серверный код проверяет права, формирует запрос к базе и возвращает результат в виде HTML или JSON.

Что такое ORM

ORM (Object-Relational Mapping) сопоставляет таблицы классам языка программирования. Разработчик работает с объектами, а библиотека генерирует SQL.

  • Python: SQLAlchemy, Django ORM.
  • JavaScript и TypeScript: Prisma, Sequelize, TypeORM.
  • PHP: Eloquent, Doctrine.
  • Java: Hibernate.
user = session.query(User).filter_by(email="anna@example.com").first()
user.name = "Анна"
session.commit()

Плюсы и минусы

ORM ускоряет разработку и защищает от части ошибок, но может генерировать неэффективные запросы. Классическая проблема — «N+1»: на каждую строку списка выполняется отдельный запрос. Её решают предзагрузкой связанных данных.

То же самое без ORM

Для сравнения — тот же результат, что и в примере выше, но через чистый SQL-драйвер, без библиотеки ORM:

cursor.execute(
    "UPDATE users SET name = %s WHERE email = %s",
    ("Анна", "anna@example.com")
)
connection.commit()

Кода меньше, но всю SQL-строку и защиту от инъекций (параметры вместо конкатенации) разработчик пишет сам. ORM берёт эту рутину на себя.

API поверх базы

Клиентские приложения получают данные через REST или GraphQL. Формат ответа обычно JSON, а база остаётся скрытой за сервером.
